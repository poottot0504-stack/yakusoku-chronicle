# 闘技大会: 非公開試作の公開判定（2026-10-26）

**状態: リリース禁止 / draft PR #31。GitHub main・Cloudflare Worker・本番DBへ展開しない。**

## 実装済み・CIで確認済み

- Lv30/50/70 の4人固定編成、レベル・ジョブ・フル装備・スキルを固定。普段の冒険状態を上書きしない。
- S 1〜3ターン=5枚、A 4〜6=3枚、B 7〜10=2枚、C 11〜100=1枚、全滅/未討伐=0枚。
- 専用通貨 state.arena.coins と装備4種（盾、魔本、指輪、チャーム）。
- 専用コイン生産/強化で残高不足なら拒否。通常の鍛冶強化は闘技装備を拒否。
- フリーマーケットでコインの出品・購入・返品を試みるローカル処理を拒否。コインはゲーム内の市場品ではない。
- 1セッションの二重決済を session.settled で防止（同じ実行プロセス内に限る）。
- 純粋なサーバー用リプレイ検証関数 (src/core/arena-proof.js) を試作。固定行動の順番・MP・対象・スキルID・最大100ターンを再計算し、偽装申告の勝敗・ターン・コインを信用しない。単体テストに合格。ただし認証済みマッチ発行・DB連携・台帳への反映は未実装。
- 攻撃重視の32試行/階層で3ターンS到達を確認。ただし実プレイヤーの達成率ではない。
- Chromiumで iPhone SE 375px、iPhone 14 390px、PC 1366px の模擬画面を確認。端末実機テストではない。

## 必須未対応: 公開を止める理由

**現在のコイン残高、勝利判定、製作・強化はブラウザ内のセーブ状態を参照する。ブラウザの開発者ツールから残高や戦闘結果、セッション情報を変更できるので、上記の入力チェックだけでは不正取得対策として不十分。**

本番公開前に、以下をゲームサーバー側へ移行し、検証完了が必要。

1. **サーバー側マッチ発行**: 認証済みユーザー、セーブスロット、クエストID、使い捨てセッションID、有効期限、サーバー乱数シードを保存。端末入力は参照のみ。
2. **戦闘ログ検証**: クライアントから選択した行動（順番・スキルID・対象・ラウンド）を提出。サーバーが配布データを使って戦闘を再生し、MP消費、命中、クリティカル、敵行動、与ダメージ、勝敗、ターン数を再計算してランクを決定。端末報告の勝敗・コイン数を信頼しない。
3. **原子的報酬処理**: (user_id, session_id) に UNIQUE 制約を設定したサーバー台帳へ成功実績を記録し、同一DBトランザクション中に残高へ加算。同じセッションID再送、並列請求、リロード後の再請求を厳密拒否。端末の settled フラグはUX用途のみ。
4. **生産・強化の原子的減算**: コイン残高の減算と所有装備の追加/強化をDBで同時実行。費用と装備候補はサーバーのホワイトリストで判定。端末側で装備IDや +値を変更しても受け付けない。
5. **セーブ改ざん防止**: クラウドセーブの arena.coins と闘技限定アイテムをアップロード値から信用しない。ログイン時はサーバー台帳を正とし、セーブ間の複製・スロット移動・二重配布も検証。
6. **マーケットのサーバー側拒否**: 既存市場サーバーの出品/購入RPC・Edge Functionで arena-coin と別名を拒否し、市場の品物に通貨として挿入できないことをテスト。ローカルの isMarketSellable だけでは安全性は保証できない。
7. **権限/公開設定**: サーバーのスキーマとコイン変更関数はサービス権限のみ。匿名・一般ユーザーによる台帳への直接書き込みと UPDATE coins をDB RLSで拒否し、レート制限と監査ログを付加。

## 公開前の追加手動テスト

- iPhone実機（Safari）とPCブラウザでタップ・戻る・バトル演出・入力中のアプリ切替を確認。
- 接続断、二重タップ、タブ2枚同時起動、端末時刻変更、セーブ復元。
- 固定編成の装備詳細、特殊ジョブ・盾二刀流、100ターン境界、敗北時の通常所持GとHP、S/A/B/C画面。
- コイン工房で装備4種のみ、普通の鍛冶・フリーマーケット・通常ショップとの混同なし。
- 難易度統計は32回の攻撃重視試行だけで判断せず、回復や防御を選ぶ実プレイヤー操作でも検証。

**公開条件**: 上記のサーバー検証と実機チェックが完了し、ユーザーから明示的な公開許可を受けた場合のみ。PRはそれまで draft のまま維持する。
