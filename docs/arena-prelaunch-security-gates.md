# 闘技大会: 公開禁止チェックリスト（2026-10-26）

**状態: Draft PR #31 のみ。main / 公開Cloudflare Worker / 本番Supabaseには変更しない。明示的な公開指示までマージ・デプロイしない。**

## 非公開で実装済み

- Lv30・50・70 の4人固定パーティ。ジョブ・全装備・スキル・レベルを固定。通常冒険のレベルや装備は変化させない。
- S（3ターン以内）5枚、A（6ターン以内）3枚、B（10ターン以内）2枚、C（100ターン以内）1枚。全滅/未討伐は0枚。
- 生産・強化できる限定装備は盾・魔本・指輪・チャームの4種類のみ。通常の素材・ゴールドでの強化を禁止。
- サーバーでのみ付与する乱数シードと対戦ID、有効期限、レート制限、勝敗・ターン数・スキル/MP/敵攻撃の決定的リプレイ検証。
- サーバーの wallet、match、gear、ledger テーブルを非公開スキーマへ配置するSQLを作成。クライアントからはDBへの直接変更権限なし。サービス専用RPCのみ。
- コイン報酬はマッチIDごとに最大1回。購入・強化はリクエストIDによる二重支払い防止、残高ロックとDBトランザクションで原子的処理。
- ブラウザからの不正なコイン・装備は、サーバープロフィールと照合するまで無効化。UIはローカルで報酬を確定せず、サーバー検証後だけ反映。
- フリーマーケット出品/購入/返品をクライアントで禁止するほか、market_listings / market_sales / market_trade_audit にDB制約を加える**ステージング用**SQLを作成。
- ゲーム側とEdge Functionのサンプル通信を接続。Edge Functionは ARENA_ENABLED=true と明示的なオリジン許可がない限りリクエストを拒否。
- 実サーバーは未配備。上記SQLも本番DBでは**一度も実行していない**。

## 自動テストで確認したこと

- ゲーム全体のNode.js回帰テスト。
- Deno Edge Functionの型検査・依存インポート検査。
- PostgreSQL 16の使い捨てDBへ権限・台帳・市場制約SQLを実際に適用して通過。匿名ユーザーの書込拒否、報酬二重請求/製作・強化二重送信、別ユーザー・別セーブ枠の残高分離、マーケットへのコイン混入を検査。
- 同じ残高に対する**並列生産リクエスト**のレーステスト。片方だけ成功することを検証。
- iPhone SE、iPhone 14、PCのChromium画面サイズ・タップ・工房ボタン・横はみ出し検査（実機テストではない）。
- 各レベル32試行の攻撃重視バトルでSランク到達可能。プレイヤー実達成率の推定には用いない。

## 公開前に絶対に残っている作業

1. **ステージング環境での認証付きEdge Function実稼働試験**。関数のtypecheckとSQL単独テストだけでは「Web→Edge→DB→Web」の本番相当の通信が動くとは断定できない。
2. **既存アカウント管理との整合**。匿名SupabaseユーザーID、アカウント連携、セーブスロット、iPhone/PCのログイン時に所有コインと装備を正しく引き継げるか確認。
3. **本番Supabaseの既存フリーマーケットEdge Functionと競合しないこと**。現在は市場テーブルに制約を加える未適用SQLのみ。公開前に既存出品データとの互換性も要確認。
4. **実機操作と通信障害試験**。iPhone Safari、PC、オフライン、二重タップ、並列タブ、モバイルの画面中断、セッション失効、開始後1時間超過、100ターン境界。
5. **獲得コイン・装備の旧ローカルセーブとの照合**。無認証ローカルアイテムを誤って承認しないこと、正常な購入品が復元されること、名前変更やアカウント切替の動作確認。
6. **運営承認**。仕様・装備バランス・データマイグレーション・リリース日時をユーザーが許可するまで絶対に公開しない。
